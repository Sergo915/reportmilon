# Симметричная компоновка графиков KPI и настройка типографики

Статус: готова к реализации

Целевой исполнитель: Model 6, reasoning medium — по прямому указанию пользователя.
ТЗ должно содержать конкретные решения и проверки без необходимости восстанавливать чат.
Подготовка этого документа не включает реализацию.

## Контекст и цель

Улучшить геометрию мини-графиков общего блока KPI, информативность осей,
уменьшить главные значения и увеличить расстояние перед стрелкой с процентом.

Проверенное состояние рабочего дерева:

- [KpiChart.vue](../src/ui/KpiChart.vue): SVG `480×142`; область данных
  X=100…460, Y=12…104. Левое и правое поля различаются. На Y показаны только
  ноль и точный максимум, на X — начало первого и последнего интервалов более
  длинной линии. Поэтому подписи X сейчас могут относиться к базе сравнения.
- [style.css](../src/ui/style.css): общий блок уже имеет ширину
  `calc((100% - 24px) * .7)` и центрирован; главные значения —
  `clamp(26px, 3vw, 36px)`, промежуток между разницей и процентом — 6 px.
- [KpiCard.vue](../src/ui/KpiCard.vue): скобки процентов уже убраны;
  стрелки используют официальный пакет `@lucide/vue`, закреплённый в
  [package.json](../package.json) как 1.70.0.
- В дереве есть незакоммиченные изменения нескольких предыдущих задач.
  Не отменять их и не заменять исходники архивной версией.
- Предыдущая работа была прервана: целевой e2e KPI прошёл 20 тестов до последней
  замены имени пакета Lucide. Полный прогон после последних изменений в этой
  подготовке не подтверждён. Старый успешный результат 453 теста относится
  к состоянию до добавления осей, сужения контейнера и замены стрелок.

## Объём задачи

Три изменения из нового запроса:

1. Симметричные графики с информативными осями X/Y.
2. Меньший размер главных чисел обоих KPI.
3. Стрелка и процент правее относительно абсолютной разницы.

Существующие ширина 70% и центрирование, иконки Lucide, отсутствие скобок,
компактные суммы, данные/фильтры/рейтинги и диалог остаются исходной основой.
Основной большой график отчёта и контракт API не менять. В этой задаче
не требуется установка новых библиотек или повторная реализация диалога.

## Требования

### Геометрия и выравнивание

- Два мини-графика имеют одинаковую ширину и высоту области данных, одинаковые
  внутренние поля и положение осей относительно своих половин контейнера.
  Левое и правое поля области данных равны; место для подписей Y резервируется
  без сдвига графика относительно центра половины. Учитывать ширину текста,
  чтобы подписи не выходили за границы.
- При двух колонках верхние и нижние границы областей данных и оси X находятся
  на одинаковой высоте. Перенос заголовка, числа или динамики в одной половине
  не сдвигает только один график: выравнивать также расположенные выше строки.
- Ниже 768 px сохраняется вертикальное расположение KPI. Оба графика имеют
  одинаковые размеры и локальные отступы; равенство абсолютных экранных Y
  для стоящих друг под другом графиков не требуется.
- Симметрия относится к геометрии, а не данным: не зеркалить линии и не
  уравнивать значения количества и стоимости. Каждому KPI нужна своя шкала Y,
  общая для обеих линий именно этого KPI.
- Сохранить нулевое основание, хронологический порядок, пропуски несмежных
  периодов, отсутствие выдуманных дней и существующие правила агрегации.

### Информативные оси

- Обе оси видимы постоянно, когда есть интервалы для построения. Подписи
  должны быть видимы без наведения, а не существовать только в tooltip.
- X подписывает интервалы **выбранного** периода. Для дневных точек — даты,
  для месячных — месяц и год. Допустима компактная запись `DD.MM` с годом
  в общей подписи периода и `MM.YYYY` для месячных точек. В tooltip обеих
  линий остаются полные реальные даты/диапазоны.
- Для достаточного количества точек показать 3–5 подписей, равномерно выбирая
  позиции из ряда, обязательно включая его первый и последний интервалы.
  На узкой ширине уменьшать число подписей в этом диапазоне и переносить
  части даты на строки, сохраняя читаемость. При одной/двух точках показать
  соответственно одну/две подписи без дублирования.
- Подписи привязаны к координатам своих точек. Если база длиннее текущего
  ряда (например, январь против февраля), нельзя брать её даты для подписей
  X выбранного периода. Длинная базовая линия и её tooltip сохраняются.
- Y имеет 3–5 равномерных делений от нуля до округлённой вверх границы,
  которая не меньше максимума **обеих** линий. Смена границы шкалы применяется
  и к геометрии линий, а не только к тексту делений.
- Количество квартир подписывать целыми числами без дробных делений.
  Суммы подписывать существующим компактным форматтером KPI со знаком ֏.
  Шаг выбирать по простому десятичному ряду 1/2/5 × 10ⁿ с округлением вверх;
  для количества шаг не меньше 1. Границу можно расширить, чтобы сохранить
  целые равномерные деления. Число делений выбирать по доступному месту.
- Если все значения нулевые, показать ненулевой диапазон оси с нулевой линией
  данных; например, для количества 0/1/2. Не дублировать несколько подписей
  «0» и не делить на ноль. Если календарных интервалов вообще нет, сохранить
  `Տվյալներ չկան` вместо выдуманного графика.
- На 1440/768/375 px подписи не накладываются, не обрезаются и не расширяют
  страницу. Резервировать место под оси и подписи, не уменьшать весь SVG
  вместе с текстом до нечитаемого размера. Можно увеличить высоту обоих
  графиков одинаково для переноса подписей. Новая горизонтальная прокрутка
  общего блока не требуется.
- Сохранить цвета линий, легенду, маркер единственной точки, доступные
  подсказки и клавиатуру Tab/ArrowLeft/ArrowRight/Home/End.

### Главные числа и строка изменения

- Для главного количества и главной суммы заменить размер на
  `clamp(22px, 3vw, 28px)`. Сохранить жирность 700 и компактное форматирование.
  Размеры заголовков, таблицы и рейтингов этим требованием не меняются.
- Между абсолютной разницей и группой «Lucide-стрелка + процент» установить
  горизонтальный промежуток 16 px вместо 6 px. Внутренний промежуток между
  стрелкой и процентом сохранить 4 px.
- Группа стрелки/процента не разрывается. Если вся строка не помещается,
  группа переносится целиком на следующую строку, начиная от левого края
  строки динамики. Не прижимать проценты к правому краю карточки.
- Не возвращать скобки. Сохранить Lucide ArrowUp/ArrowDown и цвета только
  у стрелки/процента; абсолютная разница остаётся нейтральной.
- Равенство итогов остаётся без стрелки; рост от нуля сохраняет стрелку и «—».

## Критерии приёмки

- К1. В двух колонках размеры областей данных равны, оси X и верх графиков
  выровнены; внутри каждой половины поля слева/справа симметричны. Перенос
  текста над одним графиком не нарушает выравнивание.
- К2. X показывает подписи выбранного периода, соответствующие точкам;
  число подписей адаптируется без наложений, первая/последняя сохранены.
  База большей длины не подменяет текущие даты.
- К3. Y содержит равномерные информативные деления, правильные единицы,
  целые количества; обе линии помещаются в общую шкалу KPI. Нули и одна
  точка отображаются корректно, пустая история не превращается в данные.
- К4. Главные значения имеют размер 22–28 px по заданной формуле. Перед
  группой стрелки/процента — 16 px в одной строке; при переносе группа целая.
  Нет скобок, символы стрелок не заменяют Lucide, цвета сохранены.
- К5. На широком/узком экране нет перекрытия подписей и переполнения страницы.
  Сохраняются фильтры, рейтинги, детализация и доступность точек графика.

1. Прочитать [agents.md](../agents.md), [инструкцию тестирования](../docs/testing.md)
   и текущий diff. Сохранить предыдущие изменения. Документация может отставать
   от прерванной работы; источником текущей геометрии являются исходники.
2. Изучить [KpiChart.vue](../src/ui/KpiChart.vue), [KpiCard.vue](../src/ui/KpiCard.vue),
   [App.vue](../src/ui/App.vue), [style.css](../src/ui/style.css),
   [kpi.cjs](../src/report/kpi.cjs) и [chart.cjs](../src/report/chart.cjs).
   Последний содержит расчёт шкалы основного графика; не менять его поведение
   ради KPI. При необходимости выделить отдельный чистый модуль шкал KPI.
3. Реализовать деления и выбор подписей X как проверяемые функции. Использовать
   точные десятичные операции для границ и сумм; переход к экранной геометрии
   не должен менять исходные данные. Добавить unit-тесты одновременно с логикой.
4. Перестроить геометрию SVG и размеры строк над графиками. Согласовать поля
   обоих графиков по наиболее длинным подписям; подписи и области данных не
   должны зависеть от разных случайных отступов в каждой карточке.
5. Применить размеры главных чисел и промежутки динамики. Обновить e2e и
   проверить реальную геометрию текста/осей в браузере, а не только CSS-классы.
6. Выполнить целевые проверки, затем полный `npm test`, исправить регрессии.
   Просмотреть снимки на 1440/768/375 px, в том числе перенос длинной динамики.
7. После успешных обязательных проверок запустить `docs-maintainer` согласно
   agents.md и профилю `~/.codex/agents/docs-maintainer.toml`, передать diff,
   поведение и фактические результаты. Дождаться обновления docs/ и проверить
   ссылки корневого навигатора до сдачи/архивирования/коммита.

## Проверка результата

Команды из корня проекта:

```sh
npm run test:unit
npm run test:e2e -- --runTestsByPath tests/e2e/kpi.test.js
npm test
```

Полный `npm test` включает unit/API/e2e и production-сборку. При запрете локальных
HTTP-портов/Chromium получить необходимое разрешение среды; не подменять проверку
сборкой. Исправить все выявленные регрессии. Если обязательная проверка или
документирование не завершены — сообщить конкретную причину, не объявлять
успешную сдачу. Коммит и push этим ТЗ не поручаются.
