# KPI количества заключённых квартир и общей суммы продаж

Статус: готова к реализации

## Контекст и цель

Добавить под общей панелью фильтров два прямоугольных KPI:

1. `Կնքված բնակարանների քանակ` — количество заключённых квартир.
2. `Վաճառված ընդհանուր գումար` — общая сумма продаж.

Каждая карточка показывает итог за выбранный период с учётом остальных активных
фильтров. Для конкретных периодов выводится динамика, для последних 12 месяцев
и всего времени — рейтинг периодов по показателю карточки.
Подготовка этой постановки не включает реализацию.

## Проверенный контекст проекта

- [App.vue](../src/ui/App.vue): после фильтров сейчас идут переключатели
  группировки и график; KPI нет. Фильтры применяются локально.
- [style.css](../src/ui/style.css): существующие цвета, панели и клавиатурный фокус.
- [period.cjs](../src/report/period.cjs): календарь `Asia/Yerevan`, множественный
  выбор месяцев/кварталов одного года; текущие календарные периоды ограничены
  сегодняшним днём включительно. Последние 12 месяцев включают текущий месяц.
- [filter.cjs](../src/report/filter.cjs): пересечение комнатности, комплекса,
  площади, цены и дат; включительные границы; точные десятичные операции.
  Неверный ввод сохраняет последние корректно применённые границы.
- [aggregate.cjs](../src/report/aggregate.cjs): `deals` содержит допущенные
  квартиры успешных сделок за всё время, одна запись на сделку. Проблемные
  квартиры исключены; сумма — нормализованная десятичная строка AMD.
- `/api/report` уже возвращает необходимые `deals`. Новые обращения к CRM
  или изменение HTTP-контракта для задачи не требуются.
- Месячная группировка графика ограничена текущим годом отчёта. Её столбцы
  нельзя использовать как источник KPI за произвольные годы.
- [chart.cjs](../src/report/chart.cjs) форматирует полные суммы; точная
  арифметика проекта основана на десятичных коэффициентах `BigInt`.
- Инструкции: [отчёт](../docs/report.md), [тестирование](../docs/testing.md),
  [правила проекта](../agents.md).

## Объём задачи

Добавить локальные расчёты, две карточки и необходимые автоматические тесты.
Сохранить текущие правила допуска квартир, фильтры, множественный выбор,
группировки графика, обновление снимка и общий список проблемных сделок.
KPI зависят от фильтров, но не от выбранной группировки графика.

Новые зависимости, хранилище, настройка вебхука, изменение CRM и переработка
графика не нужны. Перед реализацией учесть существующие изменения рабочего
дерева: сохранять чужие правки и работать с актуальным состоянием проекта.

## Требования

### 1. Данные и фильтрация

- Количество — число записей допущенных квартир после фильтрации. Каждая
  запись считается один раз; одинаковые значения разных сделок не схлопываются.
- Сумма — точная сумма `deal.amount` тех же записей в AMD.
- Комплекс, комнатность, площадь и цена одинаково применяются к текущему
  периоду, базе сравнения и каждому периоду рейтинга.
- При расчёте базы исходный фильтр даты заменяется базовыми датами;
  не пересекать базу с датами текущего выбранного периода.
- KPI рассчитываются из нормализованных `deals` всего снимка, а не из видимых
  столбцов. Группировка графика не меняет значения и состояние KPI.
- Использовать применённое состояние фильтров, а не ошибочный черновик полей.
  Корректное изменение фильтра пересчитывает KPI сразу и без HTTP/CRM-запросов.
- Границы дат включительны. Использовать существующий календарный контекст
  `Asia/Yerevan` и его обновление при действиях/загрузке. Автоматическое
  обновление страницы по таймеру не добавлять.
- Нет сделок в корректно определённом периоде — значение 0, в том числе
  для базы раньше первой сделки. Базу по первой сделке снимка не обрезать.

### 2. Периоды сравнения

| Режим | База сравнения или представление |
| --- | --- |
| `Ամիս` | Один месяц — предыдущий месяц; несколько — по правилам ниже |
| `Եռամսյակ` | Один квартал — предыдущий квартал; несколько — по правилам ниже |
| `Տարի` | Предыдущий календарный год |
| `Վերջին 12 ամիս` | Итог и рейтинг последних 12 календарных месяцев |
| `Ամբողջ ժամանակահատված` | Итог и рейтинг месяцев, кварталов или лет |
| `Կամայական միջակայք` | Предшествующий интервал той же длительности в днях |

В сравнительных режимах каждая карточка показывает одно суммарное значение
и одну динамику. Последовательность определяется календарным порядком,
а не порядком нажатия кнопок.

**Последовательный выбор:** N последовательных месяцев/кварталов сравниваются
с непосредственно предшествующими N месяцами/кварталами, включая переход года.

- Март–май 2025 → декабрь 2024 — февраль 2025.
- II–III кварталы 2025 → IV квартал 2024 и I квартал 2025.
- Один месяц/квартал — частный случай N=1.

**Непоследовательный выбор:** база — те же месяцы/кварталы предыдущего года.
Пропущенные периоды не включаются.

- Март + май 2025 → март + май 2024.
- I + III кварталы 2025 → I + III кварталы 2024.

**Неполный текущий период:** сравнивается с соответствующей календарной частью
базы, а не с полной базой и не с равным числом прошедших дней.

1. Сначала определить календарные периоды базы по правилам выше.
2. Полностью завершённый выбранный месяц/квартал/год соответствует полному
   базовому периоду, независимо от различий в числе дней.
3. Для незавершённого периода перенести его фактическую конечную дату назад
   на тот же сдвиг, который связывает выбор с базой: N месяцев для блока
   месяцев, 3N месяцев для блока кварталов, 12 месяцев для года или
   непоследовательного выбора. День месяца сохранить; если такого дня нет,
   взять последний день целевого месяца.
4. В непоследовательном выборе завершённые периоды базы остаются полными,
   ограничивается только соответствие текущему неполному периоду.

Примеры при сегодня 15.11.2026:

| Выбор | Текущие даты | Базовые даты |
| --- | --- | --- |
| Ноябрь | 01.11–15.11.2026 | 01.10–15.10.2026 |
| IV квартал | 01.10–15.11.2026 | 01.07–15.08.2026 |
| 2026 год | 01.01–15.11.2026 | 01.01–15.11.2025 |
| Октябрь + ноябрь | 01.10–15.11.2026 | 01.08–15.09.2026 |
| II + III + IV кварталы | 01.04–15.11.2026 | 01.07.2025–15.02.2026 |
| Сентябрь + ноябрь | 01.09–30.09 и 01.11–15.11.2026 | 01.09–30.09 и 01.11–15.11.2025 |

На 30.03.2025 неполный март сравнивается с 01.02–28.02.2025,
на 30.03.2024 — с 01.02–29.02.2024. Полный февраль прошлого года
сравнивается со всем январём, а не только с первыми 28/29 днями.

**Произвольный интервал:** при обеих корректно заполненных границах длительность
D — число календарных дней включительно. База заканчивается за день до начала
выбранного интервала и содержит D дней. Ограничение сегодняшним днём не добавлять:
текущий произвольный фильтр уже допускает будущие даты.

- 10–19 марта 2025 → 28 февраля — 9 марта 2025.
- 10–19 марта 2024 → 29 февраля — 9 марта 2024.
- Один день → непосредственно предыдущий день.
- Если одна или обе границы пусты, итог считается по действующим фильтрам,
  а динамику заменяет `Համեմատության համար նշեք երկու ամսաթվերը։`.
  Не показывать фиктивное сравнение с нулём.
- Ошибочный ввод сохраняет предыдущий корректно применённый интервал и его
  расчёт, как в существующем графике.

### 3. Динамика и форматирование

A — текущее значение, B — базовое; разница Δ = A − B.
При B > 0 процент равен Δ / B × 100.

- Количество: `+50 (+50%)`, `-50 (-50%)`, `0 (0%)`.
- Сумма: `+1 000 ֏ (+50%)`. Валюта присутствует у итогов, разницы и денежных
  значений рейтинга.
- B=0, A>0: `+50 (—)` либо `+50 ֏ (—)` — процент не определён.
- A=B=0: `0 (0%)` либо `0 ֏ (0%)`.
- A=0, B>0: отрицательная абсолютная разница и `-100%`.
- Проценты округляются до одного десятичного знака, ровная половина — от нуля;
  незначащий ноль опускается. Разделитель — запятая: `+33,3%`, `+50%`.
  Округлённый до нуля процент — `0%`, без отрицательного или положительного
  нуля; знак абсолютной разницы и цвет определяются точной Δ.
- Суммы и абсолютные разницы не округлять и не сокращать до тысяч/миллионов.
  Пробелы между разрядами и сохранённая дробная часть с точкой — как у полных
  сумм графика. Количество — целое число.
- Не переводить денежные суммы, разницы, сравнения и расчёт процентов через
  неточный `Number`; сохранять точность отрицательных дробных разниц.
- Рост — зелёный, снижение — красное, ноль — нейтральный цвет. Знак и текст
  передают смысл независимо от цвета.
- Под динамикой показывать текущие и базовые даты: `Ընտրված՝ …` и
  `Համեմատություն՝ …`. Формат — `DD.MM.YYYY`; несмежные интервалы перечислять,
  смежные можно объединять без изменения смысла. Пропуски не скрывать.

### 4. Рейтинги

В режимах последних 12 месяцев и всего времени над рейтингом остаётся итог
за выбранный период. Рейтинг занимает место динамики; сравнения с предыдущим
окном, динамики по строкам и пересчёта в среднее за день нет.
В каждой карточке сортировка идёт по её показателю, поэтому порядок количества
и суммы может различаться.

**Календарные периоды:**

- Последние 12 месяцев: ровно 12 месяцев — текущий до сегодня включительно
  и 11 предыдущих. Переключателя типа рейтинга нет.
- Всё время: месяцы/кварталы/годы от календарного периода первой допущенной
  сделки не позднее сегодня до текущего периода включительно. Начало определяется
  полным нормализованным снимком до остальных UI-фильтров, как календарь
  приложения. Фильтры меняют значения, но не исключают пустые периоды из рейтинга.
- Март 2025 и март 2026 — разные строки; аналогично кварталам. Не объединять
  одноимённые месяцы/кварталы разных лет.
- Включать периоды с нулевыми значениями. Текущий период, календарный конец
  которого позже сегодня, помечать `Ընթացիկ՝ ոչ ամբողջական`.
- Если допущенных сделок не позднее сегодня нет, рейтинг всего времени пуст.
  Для последних 12 месяцев даже при пустом снимке сохраняются 12 нулевых месяцев.

**Сортировка и строки:**

- По значению от большего к меньшему; при равенстве — более свежий период выше.
  Сравнение сумм точное.
- Равные значения имеют одинаковое место с пропусками: `1, 2, 2, 4`.
  Это правило применяется и к нулевым значениям.
- Строка: место, период, полное значение. Месяц — существующее армянское
  название + год; квартал — например `II եռամսյակ 2025`; год — четыре цифры.
  Строки информационные, не изменяют фильтры по нажатию.
- Изначально первые пять строк. При большем числе строк кнопка `Ցույց տալ բոլորը`
  раскрывает весь список; затем `Թաքցնել` возвращает первые пять.
  При равенстве на пятой строке изначально всё равно ровно пять строк.
  При пяти строках или меньше кнопки нет.
- Раскрытие увеличивает высоту карточки и страницы; используется обычная
  прокрутка страницы без отдельной пагинации или обрезки полного списка.

**Независимые переключатели и память:**

- За всё время у каждой карточки свой переключатель:
  `Ամիսներ` / `Եռամսյակներ` / `Տարիներ`. По умолчанию оба — месяцы.
- Тип хранится отдельно для каждой карточки в пределах открытой страницы при
  смене фильтров, выходе из режима «всё время» и возврате, ручном обновлении,
  в том числе после ошибки и восстановления.
- Изменение любого применённого фильтра, основного режима периода или успешная
  загрузка снимка сворачивают оба списка. Смена типа рейтинга сворачивает
  только эту карточку. Группировка графика не меняет типы и раскрытие.
- Общий сброс `Վերականգնել` и перезагрузка страницы возвращают оба типа к
  месяцам и сворачивают списки. Фильтры сбрасываются по существующим правилам.
  Дополнительного хранения в localStorage/URL нет.
- Тип рейтинга и раскрытие не меняют итог KPI и не вызывают запросов.

### 5. Интерфейс, доступность и состояния

- Порядок: фильтры → KPI → существующий блок группировки `Ցուցադրություն`
  → график. Карточки находятся внутри общей секции отчёта.
- Первая — количество, вторая — сумма. От ширины окна 768 px — две равные
  колонки; ниже — одна под другой в том же порядке. Карточки выровнены сверху,
  раскрытие одной не раскрывает вторую.
- Блок занимает доступную ширину секции с боковыми отступами 12 px. Использовать
  прямоугольные карточки в стиле фильтров: существующие шрифты/цвета,
  рамка `#DBE4EF`, скругление 12 px, светлый фон. Название, крупное значение
  и вторичная информация имеют различимую иерархию.
  Длинные суммы и подписи переносятся без обрезания цифр и переполнения страницы.
- Каждая карточка — именованная секция с точным заголовком. Переключатели имеют
  доступное имя с контекстом карточки и выбранное состояние; кнопки доступны
  клавиатурой с видимым фокусом. Раскрытие связано со своим списком и передаётся
  через `aria-expanded`.
- Изменение итога и динамики озвучивается кратко через `aria-live="polite"`;
  не помещать весь рейтинг в автоматически озвучиваемую область.
- Первая загрузка и ручное обновление: оболочки и заголовки сохраняются,
  старые числа/динамика/рейтинги скрыты; показывается `Տվյալները բեռնվում են…`,
  область помечена занятой, её управление недоступно.
- Ошибка: `Տվյալներն անհասանելի են։`, без старых/частичных чисел или фиктивных
  нулей. Повтор — через существующую кнопку `Թարմացնել հաշվետվությունը`;
  отдельной кнопки повтора нет.
- Успешный пустой результат: итоги `0` / `0 ֏`, динамика определяется реальной
  базой; при ненулевой базе текущее 0 даёт `-100%`.
- Пустой рейтинг всего времени: `Տվյալներ չկան`, без фиктивных строк и раскрытия.
  После успешной загрузки переключатели типов доступны и при пустых данных.
- Если исходная история есть, но остальные фильтры исключили все сделки,
  календарные строки сохраняются с нулями. Общий список проблем не меняется.

## Критерии приёмки

| ID | Проверяемый результат |
| --- | --- |
| A1 | Именованные карточки стоят после фильтров перед группировкой; на широком экране рядом, на узком последовательно, значения не обрезаны |
| A2 | Итоги учитывают допуск и все применённые фильтры; группировка графика их не меняет; локальные действия не создают запросов |
| A3 | Одиночные, последовательные и непоследовательные выборы используют базы раздела 2, включая переходы года |
| A4 | Неполные периоды сравниваются с соответствующей календарной частью с ограничением короткого месяца; завершённые — полностью |
| A5 | Произвольные интервалы используют включительное число дней; открытые границы дают подсказку, неверный черновик сохраняет расчёт |
| A6 | Точные итоги/разницы, проценты, нулевая база, знаки, цвета, валюта и даты соответствуют разделу 3 |

Предлагаемые новые файлы: `tests/unit/kpi.test.js`, `tests/e2e/kpi.test.js`.

### T1. Итоги, допуск и фильтры — A2, A10; unit + e2e

В текущем ноябре две подходящие квартиры Tower с суммами 100 и 200,
в базовом октябре одна с суммой 150. Добавить в оба месяца контрольные сделки,

Применить пересечение, оставляющее указанные три квартиры: количество 2,
динамика `+1 (+100%)`; сумма `300 ֏`, динамика `+150 ֏ (+100%)`.

### T2. Полные периоды и множественный выбор — A3; unit + основной путь e2e

не входящих ни в текущую, ни в базовую выборку, — контрольные по 1000.
Проверить их исключение: количество равно числу допустимых
граничных записей, суммы равны 20 × текущее количество и 10 × базовое количество.
Проверить даты базы и динамику. Дополнить январём → декабрём предыдущего года,
I → IV кварталом, годом → предыдущим годом, всеми 12 месяцами и всеми кварталами.

## Проверка результата

Команды выполняются из корня проекта. Требования окружения и установка —
в [docs/testing.md](../docs/testing.md). При первом запуске: `npm ci` и
`npm run test:install`. Нужны разрешения на локальный HTTP-сервер и Chromium.
Секреты в постановку и фикстуры не добавлять.

После добавления предложенных файлов:

```sh
npm run test:unit -- --runTestsByPath tests/unit/kpi.test.js
npm run test:e2e -- --runTestsByPath tests/e2e/kpi.test.js
npm test
```

При других названиях файлов использовать фактические пути. Полный `npm test`
обязателен независимо от адресных проверок. E2e setup сам выполняет
production-сборку; отдельный запуск сервера не нужен. Если сбой не исправлен,
сообщить причину и незавершённые проверки, не объявлять сдачу успешной.
Отчёт исполнителя содержит команды, результаты и ограничения.
