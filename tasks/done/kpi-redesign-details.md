# Общий блок KPI с компактными суммами, сравнением и детализацией сделок

Статус: готова к реализации

## Контекст и цель

Подготовка ТЗ по запросу пользователя от 05.11.2026, без реализации.
Два KPI должны стать единым визуальным блоком с двумя информационными разделами,
компактным сравнением и доступом к сделкам без перехода со страницы отчёта.

Проверенное по исходникам текущее поведение:

- [App.vue](../src/ui/App.vue) выводит `Կնքված բնակարաններ` и `Վաճառքի ընդհանուր արժեք`
  через два [KpiCard.vue](../src/ui/KpiCard.vue).
- [kpi.cjs](../src/report/kpi.cjs) считает точные итоги и динамику из нормализованных
  сделок с применёнными фильтрами. Для месяца, квартала, года и замкнутого
  произвольного интервала есть сравнение; для последних 12 месяцев и всего времени — рейтинги.
- Карточки сейчас отдельные; ниже 768 px располагаются вертикально.
  Сумма и абсолютная разница выводятся полностью, вся динамика окрашена.
  Даты сравнения повторяются в каждой карточке; графиков и детализации KPI нет.
- [aggregate.cjs](../src/report/aggregate.cjs) отдаёт в `deals` поля
  `rooms`, `amount`, `area`, `date`, `complex`, без ID/ссылки.
  CRM уже возвращает ID; безопасные ссылки строятся для проблемных сделок.
- В App.vue есть отдельный нативный диалог проблемных сделок с закрытием,
  обработкой фокуса и внешнего клика; это точка повторного использования подхода.
- Изображения [building.png](../images/building.png) и [wallet.png](../images/wallet.png)
  существуют: PNG RGBA, 1254×1254.
- Документация и e2e KPI местами используют прежние названия заголовков,
  отличающиеся от текущего App.vue. При реализации учитывать фактические названия
  из запроса и обновить связанные ожидания.

## Объём задачи

Изменить представление двух KPI, добавить мини-графики и модальную детализацию.
Расширить нормализованные данные сделок ID и безопасной ссылкой для детализации.
Сохранить правила допуска квартир, существующие фильтры, расчёты баз сравнения
для месяца/квартала/года/произвольных дат и поведение рейтингов.
Новая база сравнения нужна только режиму последних 12 месяцев.
Основной большой график отчёта, его форматирование, поля ввода фильтров,
загрузка CRM и кеширование не входят в редизайн.

## Требования

1. В правом верхнем углу раздела `Կնքված բնակարաններ` использовать building.png,
   раздела `Վաճառքի ընդհանուր արժեք` — wallet.png.
2. Все денежные значения внутри KPI и их диалога отображать компактно:
   основное значение, абсолютную разницу, рейтинги, значения мини-графиков
   и подсказок, строки таблицы и её общий итог.
   Формат: `6158173250.9` → `6,16 մլրդ ֏`. Единицы: `հազ.`, `մլն`,
   `մլրդ`; до двух знаков после запятой без конечных нулей. При округлении
   до 1000 единиц переходить к следующему порядку (1000 миллионов → 1 миллиард).
   Полную сумму при наведении не показывать: последнее решение пользователя
   «компактная везде» заменяет первоначальное требование полной подсказки.
3. Перед процентным изменением добавить стрелку вверх/вниз по направлению изменения.
4. Объединить KPI в общий горизонтальный контейнер. Между разделами — вертикальная
   линия с небольшими отступами сверху и снизу, без соприкосновения с границами.
   Общие даты выбранного и сравниваемого периодов вывести один раз снизу по центру.
   Ниже 768 px разделы располагаются вертикально внутри общей рамки,
   разделитель становится горизонтальным; даты остаются внизу.
5. Зелёным/красным показывать только стрелку и процент изменения.
6. По нажатию на любую половину открывать модальный диалог сделок с учётом текущих
   активных фильтров. Закрытие: кнопка, Escape, клик вне окна. Страница не меняется.
7. Под основными значениями и динамикой каждой половины разместить компактный
   линейный график сравнения выбранного и предыдущего периода: две линии,
   кроме отдельно согласованного режима всего времени.
8. Существующие рейтинги в режимах последних 12 месяцев и всего времени сохранить;
   график добавить также в этих режимах. Для всего времени показывать одну линию
   истории; последние 12 месяцев сравнивать с предыдущими 12 месяцами.
9. В обоих диалогах использовать предложенную общую таблицу: дата сделки,
   комплекс, комнатность, площадь и компактная сумма; сверху количество и
   компактная итоговая сумма.
   Добавить ссылку на соответствующую сделку в Битрикс24.
   ID сделки в диалоге не показывать. По умолчанию открывается выбранный период;
   при наличии базы доступно переключение на сравниваемый период.
   Ссылка в строке — `Բացել գործարքը`, открывается в новой вкладке.
   Сортировка: дата по убыванию, затем ID по возрастанию (сам ID скрыт).
   Пагинация по 50 строк; поиск и дополнительные фильтры таблицы не добавлять.

### Форматирование сумм и дат

Сокращение — только представление. Точные десятичные строки в API, суммирование,
сравнение, сортировка и проценты не округляются вслед за отображением.
Выбирать единицу по модулю числа: от 1000 — `հազ.`, от 1000000 — `մլն`,
от 1000000000 — `մլրդ`. Ниже 1000 — число без суффикса, до двух десятичных
знаков; ноль — `0 ֏`. Миллиард — максимальная единица этой задачи; большие
значения выражать в миллиардах, группируя целую часть пробелами.
Округлять до ближайшего значения с двумя десятичными знаками, половину —
от нуля, по принятому в проекте правилу точного округления. Удалять конечные
дробные нули, сохранять запятую как разделитель. После округления повторно
проверять переход к следующей единице. Не выводить отрицательный ноль.
Положительная абсолютная разница сохраняет `+`, отрицательная — `−`/`-`;
проценты сохраняют существующее форматирование. Количество квартир остаётся
целым числом без сокращений; площадь не является денежным значением.

Примеры: `1000` → `1 հազ. ֏`, `1500000` → `1,5 մլն ֏`,
`999999999` → `1 մլրդ ֏`, `-6158173250.9` → `-6,16 մլրդ ֏`.
Даты — `DD.MM.YYYY`, диапазоны — существующий `rangeText`: смежные объединяются,
несмежные перечисляются. В общей нижней области показывать выбранный период
и, только при наличии, сравниваемый. Без базы нет фиктивных дат сравнения.

### Динамика и граничные состояния

- При равных итогах показывать нейтральные `0%` без стрелки.
- При росте от нулевой базы показывать зелёные `↑` и `—` вместо процента.
- При положительной/отрицательной ненулевой разнице показывать соответственно
  зелёную `↑` / красную `↓` перед процентом. Абсолютная разница нейтральная.
  Сохранить существующий расчёт процентов, их округление до одного знака
  и определение направления по точной разнице.
- Выбранный период — синяя линия, сравниваемый — серая.
- Для последних 12 месяцев над графиком добавить абсолютную и процентную
  динамику; рейтинг оставить ниже графика. Для всего времени динамики нет.
- При незаполненной границе произвольного периода показывать одну линию
  доступной истории и существующее сообщение
  `Համեմատության համար նշեք երկու ամսաթվերը։`.
- Подсказка главной суммы доступна при наведении и клавиатурном фокусе.
  Её значение также компактное. На телефоне компактная сумма доступна в диалоге.

### Согласованное построение линий

Линии показывают значения отдельных интервалов, не накопительные итоги.
Для количества это число квартир, для стоимости — сумма AMD за интервал.

| Режим | Интервалы графика |
| --- | --- |
| Месяц, включая множественный выбор | Дни выбранных месяцев |
| Квартал, год | Месяцы |
| Последние 12 месяцев | Месяцы, две линии |
| Всё время | Месяцы, одна линия истории |
| Произвольный замкнутый период до 31 дня включительно | Дни |
| Произвольный замкнутый период длиннее 31 дня | Месяцы |
| Произвольный период с открытой границей | Месяцы доступной истории, одна линия |

Сопоставлять интервалы по порядку; пропуски несмежного выбора исключать.
Отсутствующий день не считать нулём. В подсказках показывать реальные даты,
точное количество и компактную денежную сумму соответствующих интервалов.
Существующий день без сделок
имеет значение ноль — это отличается от отсутствующего дня.

Интервалы упорядочить хронологически; сравнивать позиции двух последовательностей.
В месячном представлении частичные месяцы ограничиваются реальными границами
выборки. В дневном представлении не добавлять несуществующие даты; если одна
последовательность короче, её линия заканчивается раньше без нулевого хвоста.
Не интерполировать значения сделок и не заменять расчёты сглаженными значениями.
Обе линии одного графика имеют общую шкалу Y с нулём в основании; количество
и сумма имеют собственные шкалы. Легенда явно различает выбранный и сравниваемый
периоды. Подсказки точек доступны мышью и с клавиатуры.

Для последних 12 месяцев сохранить текущую выборку: текущий месяц до сегодня
по Еревану и 11 предшествующих. База — сдвиг этого диапазона на 12 месяцев
назад с тем же ограничением дня; короткий месяц обрабатывать существующим
календарным правилом. Пример на 15.11.2026: выбранный 01.12.2025–15.11.2026,
база 01.12.2024–15.11.2025. В конце обеих линий — соответствующие неполные ноябри.
Эта же база используется динамикой, общими датами и переключением диалога.

Для всего времени сохранить начало истории из текущего календарного контекста
и конец сегодня. Для открытого произвольного диапазона соблюдать применённую
известную границу, а отсутствующий конец оси ограничить крайними датами допущенных
сделок снимка; это ограничение только конечной оси, не новое условие фильтрации.
Будущие сделки в произвольных датах учитываются по прежним правилам.
Если история для построения отсутствует, показывать `Տվյալներ չկան`.
При существующих интервалах без сделок сохранять нулевые точки; единичную точку
показывать маркером, чтобы график не выглядел пустым.

### Диалог, взаимодействие и состояния

Оба KPI показывают одинаковую выборку квартир: заголовок диалога обозначает KPI,
через который он открыт. Набор вычислять из того же снимка и тех же применённых
фильтров, что итог; ошибочный черновик поля не подменяет последний корректный
фильтр. Для сравниваемого периода заменить только даты, сохраняя остальные
условия. Недопущенные и проблемные сделки в таблицу не попадают.

При каждом открытии выбирать текущий период и первую страницу; при переключении
периода возвращаться на первую страницу. Итоги относятся ко всей выбранной
выборке, не странице. Пустая таблица содержит `Տվյալներ չկան` и нулевые итоги.
Для одной страницы лишние действия пагинации не показывать; переходы за границы
списка недоступны. Заголовки колонок и управление — на армянском, дата и площадь
соответствуют полям отчёта. Прокрутка большого списка ограничена диалогом;
на узком экране таблица может прокручиваться внутри окна без расширения страницы.

Открытие должно работать по клику на область каждой половины и через клавиатуру
(Enter/Space), с видимым фокусом и понятным доступным именем. Кнопки рейтинга
и интерактивные точки графика выполняют собственное действие без случайного
открытия диалога. Не вкладывать интерактивные элементы в кнопку целой карточки.
Клик по главному значению открывает диалог; наведение/фокус показывает подсказку.
Общие даты и разделитель не являются третьей областью открытия.

Использовать модальное поведение: фон недоступен для управления, фокус внутри
окна, по закрытию возвращается к инициатору. Кнопка закрытия доступна при длинном
списке. Ссылка `Բացել գործարքը` открывает HTTPS URL своей сделки с
`target="_blank"` и `rel="noopener noreferrer"`; исходный отчёт остаётся открыт.
Сам диалог не меняет URL страницы и фильтры.

При загрузке/ошибке сохранить оболочку KPI и соответствующие текущие сообщения,
скрыть прежние значения, линии, рейтинги и отключить детализацию. При начале
обновления закрыть открытый диалог и подсказки. После успеха использовать новый
снимок; при пустом успехе разрешено открытие пустой таблицы. Восстановление после
ошибки выполняется существующей кнопкой обновления отчёта.

## Согласованные решения

Первый раунд интервью:
- Пользователь выбрал предложенную таблицу и ссылку на сделку в Битрикс24.
- Мини-графики — две линии, не два итоговых столбца.
- Рейтинги сохранить и добавить графики также в обоих рейтинговых режимах.

Второй раунд интервью:
- Для всего времени — одна линия истории; для последних 12 месяцев — сравнение
  с предыдущими 12 месяцами.
- Пользователь подтвердил предложенную детализацию линий по дням/месяцам,
  значения отдельных интервалов, сопоставление по порядку и подсказки.
- ID в диалоге не показывать. Выбранный период открывается по умолчанию,
  сравниваемый доступен через переключение, если он существует.

Третий раунд интервью:
- Подтверждены компактные единицы, округление и знак ֏.
- Подтверждены мобильная компоновка, ссылка без ID в новой вкладке,
  сортировка и пагинация по 50 строк без поиска.
- Подтверждены предложенные граничные состояния, цвета линий, динамика последних
  12 месяцев и доступность подсказки с клавиатуры.

Финальное уточнение: **«компактная везде»**. Это распространяется на все денежные
значения KPI, их подсказок, мини-графиков, рейтингов и диалога. Первоначальное
требование полной суммы при наведении отменено. Основной график и фильтры находятся
за пределами задачи и сохраняют свои форматы.

## Критерии приёмки

- К1. От 768 px два раздела равной ширины находятся в единой горизонтальной
  рамке; ниже — друг под другом. Разделитель не касается рамки. Иконки
  соответствуют показателям; общие даты не дублируются и центрированы снизу.
- К2. Основная сумма `6158173250.9` отображается как `6,16 մլրդ ֏`.
  Тот же формат применяется к денежным подсказкам, разнице, рейтингам, графикам
  и таблице с итогом. Сокращение не изменяет точные исходные значения и расчёты.
  Полная сумма не появляется в tooltip/title/доступном описании вместо компактной.
- К3. Направление стрелки и процент соответствуют разнице; зелёный/красный
  применены только к стрелке и проценту. Ноль и нулевая база обработаны
  по разделу граничных состояний.
- К4. Линии используют выбранную детализацию и те же применённые фильтры,
  что KPI. Значения относятся к отдельным интервалам; в подсказках есть реальные
  даты. Несмежные периоды не включают исключённые месяцы, отсутствующие дни
  не превращаются в нули.
- К5. Для последних 12 месяцев есть две линии, динамика и прежний рейтинг;
  для всего времени — одна линия и прежний рейтинг. Независимые переключатели,
  раскрытие и сброс рейтингов продолжают работать.
- К6. Обе половины открывают диалог без навигации: таблица текущего периода,
  соответствующая всем применённым фильтрам. Переключение на базу доступно
  только при наличии сравнения. Количество и сумма относятся ко всей выборке
  выбранной вкладки, а не только к странице таблицы.
- К7. В таблице нет видимого ID; ссылка ведёт на нужную сделку в новой вкладке.
  Порядок строк и страницы по 50 соответствуют согласованным правилам.
- К8. Кнопка закрытия, Escape и клик снаружи закрывают диалог; внутренний клик
  не закрывает его. Фокус удерживается в диалоге и возвращается к открывшему
  элементу. Управление доступно с клавиатуры, страница и фильтры сохраняются.
- К9. Загрузка/ошибка не показывают старые значения и не открывают устаревшие
  сделки. Успешная пустая выборка отображает нули и пустой диалог с сообщением.

Использовать искусственную CRM из [crm-fixture.cjs](../tests/support/crm-fixture.cjs)
и фиксированные часы; рабочий .env и реальные сделки для автотестов не нужны.

и сервер автоматически запускаются e2e setup.

Проверенные команды:

```sh
npm run test:unit -- --runTestsByPath tests/unit/kpi.test.js
npm run test:unit -- --runTestsByPath tests/unit/report-api.test.js tests/unit/report.test.js
npm run test:e2e -- --runTestsByPath tests/e2e/kpi.test.js
npm test
```

После реализации исправить регрессии и успешно пройти полный `npm test` (unit/API/e2e).
Затем запустить `docs-maintainer`, дождаться обновления docs/, проверить ссылки
корневого навигатора до сдачи, архивирования или коммита. Подготовка ТЗ сама по себе
не запускает документатора. Проверки приложения в ходе подготовки ТЗ не запускались.
Документатору передать корень проекта, границы изменений, diff, новое поведение,
результаты проверок и ограничения, следуя [agents.md](../agents.md) и профилю
`~/.codex/agents/docs-maintainer.toml`. Если тесты или документирование не завершены,
явно сообщить об этом пользователю; такой результат не считается успешной сдачей.
