# Глобальные фильтры отчёта и новая компоновка панели

Статус: готова к реализации

## Контекст и цель

Перестроить общий блок фильтров, добавить выбор комплекса и календарных периодов,
форматирование цены и общий сброс. Изменение любого фильтра должно отражаться
на отчёте. Подготовка этой постановки не включает реализацию.

Проверено 01.11.2026:

- [App.vue](../src/ui/App.vue) содержит панель, состояние диапазонов, переключатель
  группировки, график и список проблем. Корректный ввод применяется сразу локально.
- [filter.cjs](../src/report/filter.cjs) пересекает комнатность, цену, площадь и дату,
  но месячные категории всегда ограничены январём–декабрём года отчёта.
- [aggregate.cjs](../src/report/aggregate.cjs) передаёт нормализованные `deals`
  с комнатностью, ценой, площадью и датой. Комплекса в контракте пока нет.
  Проблемные квартиры исключаются из графиков; список проблем сейчас общий.
- [load.cjs](../src/report/load.cjs), [deals.cjs](../src/bitrix24/deals.cjs)
  и [apartments.cjs](../src/report/apartments.cjs) обеспечивают метаданные,
  загрузку и отбор квартир. Поля и элементы списков определяются динамически.
- Через разрешённый запрос только на чтение `crm.item.fields` подтверждено поле
  `Համալիր`: `enumeration`, `isMultiple: false`, варианты `Milon Tower`,
  `Milon Hills`, `Milon Plaza`. Не путать с `Նախընտրելի թաղամաս`, где есть те же
  варианты. UF-код и ID вариантов не фиксировать в реализации.
- [style.css](../src/ui/style.css) сейчас задаёт почти полноширинную панель
  с адаптивной сеткой из 1, 2 или 4 колонок и контролами высотой 40 px.
- В рабочем дереве до подготовки ТЗ уже изменены `src/ui/App.vue` и `mcp.json`.
  В частности, фактический `refresh()` использует `/api/report` без `refresh=1`
  и клиентское время вместо `snapshot.updatedAt`; документация описывает иначе.
  Эти изменения не принадлежат данной подготовке ТЗ; не откатывать автоматически.

## Требования

1. Все фильтры применяются к данным отчёта. Список проблемных сделок и его
   счётчик оставить общими, без изменения текущего поведения. Логику группировки
   и внешний вид графика не менять: месячный режим сохраняет 12 месяцев текущего
   года, даже когда фильтр охватывает другой год. Изменение месячной оси отложено.
2. Заголовок фильтра даты: `Կնքման ժամանակահատված` вместо `Կնքման ամսաթիվ`.
   Выпадающий список в следующем порядке:
   - `Ընթացիկ ամիս`;
   - `Անցյալ ամիս`;
   - `Ընթացիկ եռամսյակ`;
   - `Ընթացիկ տարի` — значение по умолчанию;
   - `Վերջին 12 ամիս`;
   - `Ամբողջ ժամանակահատված`;
   - `Կամայական միջակայք`.
   Текущие месяц, квартал и год включают весь календарный период до его конца.
   Последние 12 месяцев — текущий месяц целиком и 11 предыдущих; например,
   для 15.11.2026 это 01.12.2025–30.11.2026 включительно.
3. Новый фильтр `Համալիր`: две кнопки `Թաուեր` и `Հիլլս`.
   Источник — поле `Համալիր` в Битрикс24. `Milon Tower` соответствует `Թաուեր`,
   `Milon Hills` — `Հիլլս`. Обе включены по умолчанию; минимум одна всегда выбрана.
   `Milon Plaza` не предлагается как вариант.
4. Фильтр комнат: `Սենյակների քանակ`, кнопки от 1 до максимума и дополнительная
   кнопка `Բոլորը` слева от 1. По умолчанию выбран `Բոլորը`.
   Нажатие отдельной комнаты из состояния `Բոլորը` выбирает только её.
   Затем можно добавлять и отключать отдельные комнаты; последнюю выбранную
   комнату отключить нельзя. Нажатие `Բոլորը` возвращает выбор всех комнат.
5. Площадь: заголовок `Մակերես (մ²)`, диапазон с полями `Սկսած` / `Մինչև`;
   единицы внутри полей убрать.
6. Цена: заголовок `Բնակարանի արժեք (֏)` вместо `Բնակարանի ընդհանուր արժեք`,
   диапазон с полями `Սկսած` / `Մինչև`; знак валюты внутри полей убрать.
   При вводе цифр сразу отображать пробелы между группами тысяч, например
   `12500000` → `12 500 000`. Дробные значения с точкой или запятой сохраняются.
7. В левом верхнем углу панели — `Զտիչներ`, в правом — кнопка `Վերականգնել`.
   Нажатие возвращает все фильтры к значениям по умолчанию.
8. Удалить из header надпись об анализе недвижимости
   (в исходнике `ԱՆՇԱՐԺ ԳՈՒՅՔԻ՝ ԲՆԱԿԱՐԱՆՆԵՐԻ ՎԵՐԼՈՒԾՈՒԹՅՈՒՆ`).
9. `Կնքված բնակարանների հաշվետվություն` разместить под `Հաշվետվություններ`,
   над разделительной линией.
10. Панель сделать на 30% уже прежней и центрировать. Две строки фильтров:
    первая — период / комплекс / комнаты; вторая — площадь / цена.
    На широком экране ширина равна 70% прежней ширины панели, первая строка
    состоит из трёх равных блоков, вторая — из двух равных блоков.
    Новую адаптивность для узких экранов не реализовывать: она отложена
    пользователем в отдельную задачу. Не вводить новую одноколоночную компоновку
    как часть этой задачи; существующие правила узких экранов специально не менять.
11. При `Կամայական միջակայք` показывать два поля дат под списком периодов.
    Пустая граница не ограничивает соответствующую сторону. При переходе
    на пресет поля скрываются, их значения сохраняются и восстанавливаются
    при возврате к произвольному периоду. Пока выбран пресет, сохранённые
    произвольные даты не ограничивают его.

## Сохраняемое поведение

См. [отчёт](../docs/report.md) и [тестирование](../docs/testing.md).
Диапазоны включительны; пустая граница открыта. Цена и площадь допускают
неотрицательные дроби с точкой или запятой и сравниваются точно через BigInt.
При неправильном или обратном диапазоне сохраняется последняя корректная пара,
показывается ошибка, остальные фильтры продолжают действовать.
Фильтрация не отправляет запросов в API/CRM. Обновление сохраняет состояние
фильтров; перезагрузка страницы сбрасывает его, постоянного хранения нет.
При загрузке и ошибке элементы фильтров сейчас скрыты за уведомлением.
Сохранить эти правила. Сброс фильтров — новое отдельное действие, описанное ниже.

## Детальные правила и границы задачи

### Периоды и произвольные даты

Календарные границы определять в `Asia/Yerevan`, как принято в проекте.
Пресеты вычислять по текущей календарной дате при инициализации, выборе пресета,
сбросе и успешном обновлении данных; не привязывать к дате последней сделки.
Отдельный таймер переключения периода в полночь в задачу не входит.
Обе границы включительны. `Ամբողջ ժամանակահատված` снимает только ограничение даты.

Пример при текущей дате 15.11.2026:

| Пресет | Начало | Конец |
| --- | --- | --- |
| Ընթացիկ ամիս | 01.11.2026 | 30.11.2026 |
| Անցյալ ամիս | 01.10.2026 | 31.10.2026 |
| Ընթացիկ եռամսյակ | 01.10.2026 | 31.12.2026 |
| Ընթացիկ տարի | 01.01.2026 | 31.12.2026 |
| Վերջին 12 ամիս | 01.12.2025 | 30.11.2026 |
| Ամբողջ ժամանակահատված | Нет ограничения | Нет ограничения |

При первом выборе произвольного периода оба поля пустые, ограничение даты снято.
Использовать существующие нативные поля дат и календарь, с подсказками
`Սկսած` / `Մինչև`. Их черновики, ошибки и последнюю корректную пару хранить
отдельно от пресета. Возвращение из пресета восстанавливает эти значения;
при некорректном черновике действует последняя корректная произвольная пара.
Скрытые ошибки произвольных дат не препятствуют применению пресета.
Сброс очищает и сохранённые произвольные даты.

Дата сделки по-прежнему берётся из поля CRM `Կնքման ամսաթիվ`.
Переименование фильтра не меняет поиск поля CRM, переключатель группировки
и подписи оси X. Алгоритм графика и 12 категорий текущего года сохраняются.
Например, фильтр 2025 года может дать ненулевой комнатный график, но нулевой
месячный график за 2026 год. Это известное согласованное ограничение этой задачи.

### Комплекс и контракт данных

В серверном загрузчике найти единственное поле с точным заголовком `Համալիր`,
проверить тип `enumeration`, `isMultiple: false` и единственность элементов
`Milon Tower` / `Milon Hills`. Их ID определять из актуальных метаданных,
значение сделки сравнивать с ID, а не с отображаемой подписью. Строковый и
числовой ID обрабатывать так же строго, как в существующем отборе квартир.
Ошибочные или неоднозначные метаданные дают существующую безопасную ошибку
загрузки отчёта (`CRM_READ_ERROR`, HTTP 502), без частичного успеха.

Предлагаемое расширение контракта `/api/report`: добавить к нормализованной
записи `deals` поле `complex` со значением `tower`, `hills` либо `null`.
`null` означает значение вне двух поддерживаемых вариантов, в том числе Plaza,
пустое, неизвестное или некорректное значение поля. Не передавать в браузер
сырые записи CRM. Не менять общий допуск квартир, существующие причины проблем
и формат `problems`: комплекс является дополнительным условием фильтрации,
а не новой причиной проблемной сделки.

В UI всегда выбран непустой набор из `tower` и `hills`; поэтому записи
с `complex: null` не проходят фильтр даже при двух включённых кнопках.
Список проблем и его счётчик остаются прежними независимо от выбора комплекса.
Между выбранными комплексами действует «ИЛИ», между разными фильтрами — «И».
Нажатие последней включённой кнопки комплекса оставляет её включённой.

Сохранить серверные агрегаты и их прежнюю логику для совместимости, дополнив
только нормализованные данные. UI пересчитывает показанный результат из `deals`
с учётом общих фильтров, как сейчас. Внутренние вызовы расчёта без заданного
условия комплекса не должны неявно отбрасывать записи.
Кеш справочников/отчёта и обычную CLI не перестраивать; чтение нового поля
добавить через существующий механизм `additionalFields` и `select` отчёта.

### Комнаты и диапазоны

Максимум комнат, пропуски в диапазоне 1–N и согласование набора после обновления
сохранить по текущим правилам: N вычисляется по допущенным квартирам снимка
до применения пользовательских фильтров. Смена комплекса или периода не
перестраивает кнопки комнат. При обновлении новые номера включаются,
исчезнувшие удаляются; если выбор стал пустым при непустом наборе — выбираются все.

`Բոլորը` означает весь доступный набор и активно, когда выбраны все комнаты.
При переходе к подмножеству активны отдельные выбранные номера, `Բոլորը`
неактивно; при восстановлении полного набора оно снова активно.
Из состояния всех комнат нажатие номера выбирает только этот номер.
При отсутствии доступных комнат `Բոլորը` остаётся видимым состоянием по
умолчанию, числовых кнопок нет и фиктивные категории не создаются.

Пустые площадь и цена не ограничивают данные. Не менять существующую
валидацию, включительность границ и точные десятичные сравнения.
Для цены отделить форматированный текст от нормализованного числового значения:
`12 500 000,50` соответствует `12500000.50`. При вставке поддержать число
без группировки и с пробелами между разрядами. Группируется только целая часть;
дробную часть не округлять. Сохранить возможность ввода дробного разделителя,
исправления середины строки, Backspace/Delete и выделения текста без скачка
курсора в конец. Некорректный ввод не превращать молча в другое корректное число.
Применённое числовое значение не форматировать через `Number`, чтобы не потерять
точность больших сумм. Форматирование площади в задачу не входит.

### Сброс, загрузка и оформление

`Վերականգնել` одним действием устанавливает текущий год, оба комплекса,
все комнаты (`Բոլորը`), пустые цену и площадь, очищает ошибки, черновики
и сохранённый произвольный период. Отчёт пересчитывается сразу без запроса
к API. Группировку графика сброс не меняет. Повторный сброс безопасен.
При обычном обновлении сохраняются выбранные фильтры, черновики и ошибки;
при перезагрузке страницы устанавливаются defaults. URL/localStorage не добавлять.

В успешном состоянии, в том числе при пустом результате, заголовок `Զտիչներ`
и сброс видны. Во время загрузки и после ошибки сохранить существующий режим
уведомления вместо элементов фильтрации; новая кнопка сброса тоже недоступна.
Сохранить сообщения пустого результата, загрузки и ошибок.

Для широкой компоновки считать прежнюю ширину по существующим боковым отступам
панели 12 px внутри секции: новая внешняя ширина панели равна
`0.7 × (внутренняя ширина секции − 24 px)`, с центрированием.
Применять широкую компоновку в области, где прежняя панель переходила к широкой
сетке (порог 1100 px доступной панели до сужения); не оценивать этот порог
по уже уменьшенной панели. Это техническое продолжение существующего порога,
не отдельная разработка адаптивности. На меньшей ширине сохранить существующие
правила переноса, не добавлять новые мобильные макеты или брейкпоинты.

В первой строке три равных блока, во второй два; кнопки внутри комнат могут
переноситься при большом N, а поля произвольных дат располагаются внутри первого
блока под списком. «Две строки» относится к группам фильтров, не запрещает
увеличение высоты отдельного блока. Сохранить существующие цвета, размеры
контролов и оформление, кроме явно заданных изменений. Кнопки с текстом
должны вмещать названия; ширина 40 px остаётся для числовых кнопок комнат.
Доступные имена соответствуют новым подписям, ошибки связаны с полями,
состояние кнопок доступно через `aria-pressed`, управление доступно с клавиатуры.

Правки header входят в задачу: порядок — `Հաշվետվություններ`, затем h1
`Կնքված բնակարանների հաշվետվություն`, затем линия. Удалить строку категории.
Сохранить существующие размеры 15/25 px, цвета, жирность и центрирование
оставшихся заголовков. Остальное оформление графика, подписи и его управление
не изменять. Существующие несвязанные изменения `App.vue`/`mcp.json` не откатывать;
проверять отдельно, если они вызывают падения старых тестов.

3. Обновить состояние `App.vue`: пресет/произвольные даты, комплекс, `Բոլորը`,

4. Перестроить панель и header в `App.vue`/`style.css` по требованиям.
5. Обновить fixture и существующие unit/API/e2e; заменить ожидания изменённых
   defaults, текстов и геометрии, сохранив проверки неизменённого поведения.
   Не ослаблять тесты ради прохождения и не добавлять отдельный тестовый стек.

## Проверка результата

Существующая инфраструктура: Jest, e2e через Playwright/Chromium.
Команды из корня проекта:

```sh
npm run test:unit -- --runTestsByPath tests/unit/filters.test.js
npm run test:e2e -- --runTestsByPath tests/e2e/report.test.js
npm test
```

При первичной установке: `npm ci`, `npm run test:install`.
Полный прогон включает unit/API и e2e; e2e автоматически собирает production-клиент.
Незавершённые проверки и неисправленные сбои не являются успешной сдачей.
На этапе подготовки ТЗ тесты не запускались, функционал не менялся.

## Согласованные решения

- Список проблемных сделок пока не менять; его фильтрация отложена.
- Логику и внешний вид графика пока не менять, включая месячную ось.
  Работа охватывает общую панель фильтров и исходные изменения header;
  включение header повторно подтверждено пользователем.
- Текущие календарные периоды брать целиком, последние 12 месяцев — текущий
  и 11 предыдущих.
- Названия переключателей группировки и оси X сохраняются; переименование даты
  относится к заголовку фильтра.
- Комнаты допускают множественный выбор: из `Բոլորը` отдельная кнопка выбирает
  только эту комнату; далее можно добавлять комнаты, последнюю отключить нельзя.
- Произвольный период показывает два поля под списком; границы можно оставлять
  открытыми, значения сохраняются при переключении на пресет и обратно.
- Широкий экран: 70% прежней ширины панели, равные колонки в каждой строке.
  Разработку адаптивности узких экранов пользователь явно отложил.

- Для тысяч согласован пробел: `12 500 000`; дробные значения с точкой/запятой
  сохраняются.
- Удаление категории header и перенос главного заголовка над линией подтверждены.

Существенных открытых вопросов нет. Постановка готова к самостоятельной реализации;
сама подготовка ТЗ не является поручением начать реализацию.
